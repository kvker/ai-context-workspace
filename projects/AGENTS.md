# projects 目录说明

`projects/` 是具体业务交付物的根目录。每个子目录代表一个独立工作单元，可以是代码工程、文档集、数据集、设计稿目录等；交付物本体写入此目录，而非 `artifacts/`。

## 职责边界

- 只写与交付物强相关的变更：代码、测试、构建配置、依赖，以及随交付物一起演进的 README、API 和架构文档。
- 不写宏观计划、方案、TODO、排期、进度、评审记录或任务状态；这些属于 ACW 的任务上下文，写入 `artifacts/`，长期稳定的写入 `background/` 或 `conventions/`。
- 工作单元是 Git 仓库时不改变上述归属，仓库内只保留代码强相关变更；代码内 TODO 注释属于交付物本身，可以保留。

## AI 行为

- 每个子目录视为独立项目，按需读取其内部结构和文件。
- 新建项目时创建独立子目录；完成后运行 `$an-refresh`，由 `background/workspaces.md` 维护工作单元清单。根 `AGENTS.md` 不保存动态项目表。
