# knowledge 目录说明

`knowledge/` 存放从工作区材料和用户输入中整理出的工作区级事实（含工作单元清单与关系）和跨工作单元事实，包括工作区定位、主要材料、领域事实和可复用能力的事实清单（工具、入口、命令及位置）。它是可刷新的事实层，不是不可变档案，也不是任务过程记录。

## 维护方式

- 需要理解工作区事实时，按需读取相关文档；不要只写不读。
- AI 可在任务执行、初始化或刷新过程中持续维护本目录，不需要等待专门流程。
- 用户明确限定只读、审查或指定范围时，遵守该范围，不因本目录可写而越界。
- 发现稳定事实时可直接增量写入；有来源但尚未确认的内容标记为“待确认”并分节记录。
- 写入必须标注来源，保留仍有效的人工内容，不整篇重写。
- 无来源的猜测、一次性执行细节、临时问题、计划、方案、TODO、排期、进度、决策、评审记录和任务状态不写入本目录；有 Artifact 时留在 `artifacts/`，L0/L1 无 Artifact 时只保留在当轮回复中。
- 需要系统性校准全工作区知识时，运行 `$an-refresh`；它不是知识写入的唯一入口。
- 知识文档与 `projects/` 材料冲突时，先以材料事实为准，并在本轮 execution 摘要或最终回复中说明冲突。
- 任务内写入后，在本轮 execution 摘要或最终回复中报告变更、来源和待确认项。

## 边界

- `knowledge/` 回答“是什么”：工作区级事实（含工作单元清单与关系）、材料和领域知识；不存放交付物本体，交付物写入 `projects/`，随交付物演进的 README、API 和架构文档也留在 `projects/`。
- `conventions/` 回答“怎么做”：流程、规范、长期协作规则；规范正文变更需显式更新，对话记忆按 `conventions/rules.md` 机制写入。
- `artifacts/` 记录任务过程、计划、进度、决策和检查证据。

## 证据

- `projects/` 当前材料和用户明确输入可以直接作为事实来源。
- Artifact 作为二手线索时，以 `an-refresh` 扫描结果 `acceptable: true` 为准，并确认 `diagnostics` 中没有 `INVALID_ARTIFACT_INDEX` 等索引错误；任务内直接观察到的事实不受此限。
- 已确认事实与待确认推断必须分节记录；“待确认”内容不作为执行前提或归档证据。
- “直接观察”指当前 `projects/` 材料、用户明确输入和当前任务的实际执行观察；他人或非当前任务的未归档 Artifact 中的记录仍属二手线索。
