# 校准知识

根据工作区事实增量校准上下文，不预设工作类型，不把任务过程直接写成长期知识。

## 流程

```text
扫描 → 比较 → 更新 → 报告
```

## 扫描

```bash
node .agents/skills/an-refresh/scripts/scan-projects.mjs --root projects --artifacts artifacts --format markdown
```

需要保存结构化结果时：

```bash
node .agents/skills/an-refresh/scripts/scan-projects.mjs --root projects --artifacts artifacts --write .agents/knowledge-scan.json
```

扫描内容包括：

- 工作单元、目录、文件类型和主要材料变化
- README、索引、配置和已有说明的路径；脚本只做清单，语义由 AI 按需读取实际文件
- 声明的工具、脚本和可复用动作
- 已归档任务的 `artifact.json`、`review/review.json` 和完结摘要

扫描结果标记 `truncated: true` 时，只能作为部分清单使用。工作区扫描可用 `--limit 100000` 以内的安全整数扩大；归档扫描可用 `--archive-limit 100000` 以内的安全整数扩大。仍然截断时针对目标材料继续检查，不能据此断言不存在其他内容。

## 更新

知识维护不是本流程的专属权限；任务中发现的稳定事实可直接增量写入 `knowledge/`，本流程负责系统性校准。

扫描结果为 AI 比对现有 `knowledge/` 提供输入；差异判断由 AI 完成，不由脚本自动得出。

1. 读取 `knowledge/` 和相关 `conventions/` 文档。
2. 将扫描结果与现有记录比较，只更新有事实依据的变化。
3. 明显事实变化可直接更新；涉及主题定位、业务含义或用户意图且证据不足时标记待确认。
4. 保留仍有效的人工内容，不整篇重写，不因材料暂时缺失而直接删除知识记录。
5. 更新后报告变更、来源、未变更项和待确认项。

`$an-refresh` 是规范正文的显式更新入口：无论用户要求还是 AI 判断必要时运行，对 `conventions/structure.md` 和 `conventions/style-guide.md` 的变更都必须在本轮回复中列出变更点、来源和范围；用户明确限定只读、审查或范围时不得更新规范正文。其他任务不得静默改写规范正文。

## 默认更新目标

| 内容 | 目标 |
|------|------|
| 工作区定位和主要材料 | `knowledge/overview.md` |
| 工作单元清单、关系和可用动作（工作区级索引） | `knowledge/workspaces.md` |
| 目录职责与组织规范（规范视角） | `conventions/structure.md` |
| 命名、格式和标注约定 | `conventions/style-guide.md` |
| 稳定领域事实 | 已存在的相关 knowledge 文档 |

只有事实足以支撑且有长期复用价值时才新增知识文档。不要固定要求 `product`、`tech`、`domains` 或 `features` 等行业相关文件。

## 约束

- `projects/` 材料、用户明确输入和当前任务的实际执行观察是事实来源；冲突时报告差异。
- Artifact 作为二手知识线索时，以 `an-refresh` 扫描结果 `acceptable: true` 为准，并检查 `diagnostics`；任务内直接观察到的事实不受此限。取消归档不进入稳定知识。
- 任务内直接观察指当前 `projects/` 材料、用户明确输入和当前任务的实际执行观察；他人或非当前任务的未归档 Artifact 中的记录仍按二手线索处理。
- 一次性执行细节和临时问题不进入稳定知识；有来源但未确认的推断只进入“待确认”分区，无来源推断不写入。
- 扫描脚本无法识别语义时，由 AI 阅读实际材料补充，不把文件名当成业务事实。
- 扫描输出中的 `diagnostics` 非空时，必须先报告限制；错误项不得被解释为“没有内容”。
- 只有扫描结果中 `archivedReviews.items[].acceptable: true` 的归档任务可以作为 Artifact 知识线索。
- 从归档内容提取知识时，不复制旧目录名、旧只读门禁或旧证据规则；发现时先在回复中报告。
